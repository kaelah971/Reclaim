## Qualitative Findings

1. The homepage has competing calls to action. Respondents identified `Protect a payment`, `See how it works`, and `Explore the live demo case` as creating ambiguity about the intended first step.
2. `Protect a payment` should be the clear dominant primary action.
3. Static homepage values such as payment amount, date, and status resemble interactive fields and create confusion about whether the user is expected to enter information there.
4. First-time users need an explicit step-by-step preview before initiating a protected payment.
5. The public product should clearly explain terms, wallet connection, deposit, delivery evidence, review/resolution, release timing, settlement receipt, which party performs each action, and when funds become protected versus released.
6. `/payments/new` should either preview required fields before entry or become a guided preflight/checklist flow.

## Intended Improvement Areas

- Establish one unambiguous homepage first action, with `Protect a payment` as the dominant CTA.
- Distinguish static product demonstrations from interactive inputs.
- Add a step-by-step first-time payment preview.
- Make the full protected-payment lifecycle and participant responsibilities explicit.
- Improve `/payments/new` with a preflight or guided checklist before data entry.
